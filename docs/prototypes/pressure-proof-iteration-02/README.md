## Fixture discipline

Every identity, price, variant, batch, proof record, relationship, dimension, source, availability, eligibility result, cart condition, and media object in this package is visibly synthetic. Bracketed values and placeholder names deliberately avoid a plausible live-catalog appearance. No competitor copy, imagery, color system, or trade dress is present.

The actual `docs/brand/assets/blowin-smoke-logo.png` appears only on the Home page at a spacious editorial scale. Its opaque padded canvas is preserved. The persistent header uses live text because a compact production mark has not been supplied and must not be fabricated.

## Static interaction notation

Hover, focus, selected, blocked, loading, error, changed, drawer, and modal-like layer states are labeled visual specimens. They do not imply event handling, persistence, validation, live data, focus management, network behavior, checkout readiness, or any other functional service. No JavaScript is required for the representative exports.

## Typeface test

The CSS separates display, interface/body, and data roles. Only the display stack may request `Arial Narrow`; interface/body/data use `"Archivo", Arial, "Helvetica Neue", sans-serif`. Supported prototype weights are limited to 400, 500, 600, 700, and 800. No font file is bundled or downloaded. The evaluation records the computed face and available rendered weights.

## Iteration 02 decisions

- Red approach B is selected for prototype evaluation: a near-black Pressure field with observed logo red `#ED2925` restricted to the unmodified logo and a non-text witness bar. This is not a production palette decision.
- Status density is explicit: inline cue, Decision Summary, and Full Evidence.
- Current Proof is an information/provenance state, not generic success.
- PDP purchase blockers remain disabled while recovery links remain enabled.
- Compact two-column cards are limited to low-consequence browsing at the 390 test canvas; evidence-heavy cards span full width, and all collapse at 320.
- Quick Cart confirms and routes inside a viewport-contained drawer; Full Cart owns expanded order evidence.
